# CraveHub / DineIQ 🍽️

An AI-powered restaurant dining and kitchen management platform featuring intelligent food recommendations, order tracking, automated kitchen display queues, AI-driven demand prediction, and customer feedback sentiment analysis.

---

## 🚀 Key Features

### 1. 🍕 Smart Food Recommendations & Pairings
- **Popular Dishes**: Dynamically aggregates top-selling items based on historical orders.
- **Cross-Category Complementary Suggestions**: Recommends pairing items based on the user's cart (e.g., ordering **Pizza** suggests **Truffle Fries** or **Cold Coffee**).
- **1-Click Upsell**: Customers can add recommendations directly inside the cart drawer before checkout.

### 2. 📈 AI Demand Prediction (Python ML)
- **Historical Analysis**: `ml/demand_forecast.py` reads historical orders to analyze volume trends, category popularity, and day-of-week patterns.
- **Tomorrow's Forecast**: Predicts category and item-level demand (`High`, `Medium`, `Low`) with projected volumes (e.g., *"Pizza demand tomorrow: HIGH (Est: 25-35 orders)"*).
- **Actionable Kitchen Advice**: Guides kitchen staff on ingredient prep before rush hours.
- **Admin Dashboard Integration**: Real-time forecast widgets with color-coded demand pills and percentage trends.

### 3. 💬 Feedback Sentiment Analysis
- **Nuanced Sentiment Classifier**: Categorizes customer reviews into **Positive**, **Neutral**, or **Negative**.
- **Negation & Contradiction Handling**: Intelligently handles phrases like *"not good"*, *"never again"*, and resolves contradictory reviews (e.g., 5-star ratings with severe complaint text).
- **Admin Sentiment Meter**: Displays sentiment counts alongside a visual percentage distribution meter.

### 4. ⏱️ Live Order Tracking
- **Dedicated Tracking View** (`/orders/:id/track`): Real-time polling with a pulsing status badge.
- **Preparation Stage Tracker**: Visual progress through `placed` → `preparing` → `ready` → `completed`.
- **Dynamic ETA Banners**: Contextual estimated wait times and kitchen updates.
- **Seamless Flow**: Direct redirect from checkout to live tracking.

### 5. 📱 Responsive Mobile UI & UX Polishing
- **Mobile Navigation**: Clean toggle menu for screens under 720px, giving full access to Menu, Cart, Orders, Kitchen, and Admin areas.
- **State Feedback**: Loading spinners, empty states for searches and queues, and dismissible alert banners.

### 6. 🌱 Automatic Demo Seeding
- On first start with an empty database, the server automatically seeds:
  - 8 gourmet menu items with inventory tracking
  - Demo accounts for Admin, Kitchen, and Customer
  - 9 realistic historical orders spanning past 5 days
  - Customer feedback reviews across positive, neutral, and negative sentiments

## 🛠️ Tech Stack & Architecture

- **Frontend**: React 18, Vite, React Router 6, Vanilla CSS3 (Custom Design System)
- **Backend**: Node.js, Express, Mongoose (MongoDB ODM), JWT Authentication, bcryptjs
- **Machine Learning / Analytics**: Python 3 (CLI / Stdin Subprocess Engine)
- **Database**: MongoDB (Local or MongoDB Atlas)

## 📦 Getting Started

### Prerequisites
- Node.js (v18+)
- Python 3.10+
- MongoDB running locally on `mongodb://127.0.0.1:27017` or a MongoDB Atlas URI

### 1. Backend Setup
```bash
cd backend

# Copy sample environment configuration
cp .env.example .env

# Install dependencies
npm install

# Start development server
npm run dev
```
> The API will listen on `http://localhost:5000` and seed initial menu items, demo accounts, sample orders, and feedback automatically.

### 2. Frontend Setup
```bash
cd frontend

# Install dependencies
npm install

# Start Vite dev server
npm run dev
```
> Open `http://localhost:5173` in your browser.

### 3. Python ML Demand Prediction
You can test the standalone forecasting script directly:
```bash
# In project root
python ml/demand_forecast.py
```
> The backend automatically invokes this script via `GET /api/analytics/demand-forecast`.

### 4. Deploy to Render

This repository includes a Render Blueprint and Dockerfile for a single web service. The service builds the React frontend, serves it from Express, and runs the API and Python forecast script together.

1. Create a MongoDB Atlas cluster and database user. Allow connections from Render in Atlas Network Access, then copy the cluster connection string.
2. Push this repository to GitHub and choose **New + > Blueprint** in Render.
3. Set the Blueprint values for `MONGODB_URI`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD`. Use a strong, unique admin password. `JWT_SECRET` is generated by Render.
4. Deploy. Render builds the frontend and backend into one service; open the service URL when its `/api/health` check passes.

The production server seeds the menu and inventory, creates the admin account from the configured environment variables, and does not create the demo users or sample orders. Customers can register through the app. No `VITE_API_URL` is needed because production uses the same-origin `/api` path.

## 📡 API Reference

### Public / Customer Routes
- `GET  /api/menu` - Fetch menu items (supports `?category=` and `?search=`)
- `GET  /api/menu/recommendations` - Top popular items
- `POST /api/menu/recommendations/complementary` - Complementary cross-category suggestions
- `POST /api/orders` - Place a new order *(Auth required)*
- `GET  /api/orders/mine` - Retrieve current customer's orders *(Auth required)*
- `GET  /api/orders/:id` - Get live tracking status for a specific order *(Auth required)*
- `POST /api/feedback` - Submit feedback and calculate sentiment *(Auth required)*

### Kitchen Routes *(Kitchen / Admin only)*
- `GET   /api/orders/active` - List active orders in queue (`placed`, `preparing`, `ready`)
- `PATCH /api/orders/:id/status` - Advance order status

### Admin Routes *(Admin only)*
- `GET   /api/analytics/overview` - Today's orders, revenue, top dishes, stock alerts, sentiment totals
- `GET   /api/analytics/demand-forecast` - AI-generated demand forecast by category/item
- `GET   /api/menu/admin/all` - View all menu items
- `POST  /api/menu` - Create new dish
- `PATCH /api/menu/:id` - Toggle availability or edit details
- `PATCH /api/inventory/:id` - Adjust stock levels
- `GET   /api/feedback` - View all customer reviews with sentiment tags
